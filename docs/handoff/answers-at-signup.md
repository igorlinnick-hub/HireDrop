## Состояние

Список вопросов — один: `modules/employer_answers.py` (`QUESTIONS`, `OPT_OUT`, `SINCE`).
В проде бэкенд: `GET /profile/employer-answers` (все вопросы + ответы в профиле),
`POST …/suggest` (подсказки из резюме), `POST /profile/employer-answers` (сохранение).
Вопросы: `school`, `degree`, `salary_expectation`; «у меня этого нет» (`no_linkedin`,
`no_degree`, `no_salary_expectation`) едет вместе с вопросом (`opt_out`). Колонки в `profiles`
применены (`migrations/add_employer_answer_fields.sql`).

**Сайт #228 смержен 2026-10-02 00:44 UTC.** Шаг 7 «Answers» в визарде (11 шагов), та же форма
в гейте Start, Education + Salary expectation в Settings. С этого момента **каждый старый
аккаунт, включая аккаунт Игоря, получит форму из 3 вопросов на первом Start** после мержа —
это ожидаемое поведение, не баг. Новый юзер отвечает при регистрации, к первому Start у него
уже нечего спрашивать.

## Сломано / не доделано

- У шага «Answers» шапка заимствована у шага 1 (`step-1.jpg`) — нужен свой рендер.
- «Не живу в США» теперь останавливает регистрацию на шаге 7 (раньше — только первый Start).
  Продуктовое решение за Игорем.
- **Расширение не читает `profile.school` / `degree` / `salary_expectation`** — потребитель
  пока только ночная смена (`scripts/night_shift/`). Пока content.js их не использует, #228
  почти не ускоряет подачу через расширение — только серверную. Колонка нарочно не
  `desired_salary`: её `content.js` читает парсером «только цифры».
- `background.js` глотает любой отказ `POST /campaign/start` (`catch {}`): старт из попапа
  игнорирует 403 гейта. Хвост #271, ext-лейн.
- Кэш подсказок из резюме — в памяти процесса (2 воркера = до 2 чтений на резюме).
