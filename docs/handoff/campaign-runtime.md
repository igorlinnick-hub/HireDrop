# campaign-runtime

Обновлено: 2026-09-26 · ветка: main · ext: **1.8.20** в репо (в CWS 1.8.19)

## Состояние

Цикл: скрейп → фильтры → fit-гейт → walk → подача; окно автоматизации **видимое** (политика CWS).
Порядок стадий Indeed → ZR → ATS-пул, пул последний и достижим только через `PLATFORM_EXHAUSTED`,
поэтому «конец прогона» живёт в одном месте (`pickNextStage`).

**Stop = два адресата, расширение ПЕРВЫМ, каждый в своём `try`** (website #208; было сломано в
четырёх кнопках). Обратный порядок = fail-open: ошибка бэкенда съедала остановку (09-24: Stop в
20:57, заявки до 22:00). Разбор, обе страховки и отсутствующий ack (`ping.js:119`) — в шапке
`../jobflow-website/lib/campaign/stop.ts`, под тестом.

**Паузы-с-передачей-человеку** (капча #72, логин-стена, стена согласия #182) — одна схема, три
правила, каждое куплено живым багом (аудит `docs/reviews/2026-09-25-captcha-resume-audit.md`,
код в #257 + `490a02e`):
- **Ретайр состоянием, не контекстом.** Полностраничную стену решает НАВИГАЦИЯ, убивающая
  content-script, — поэтому «человек решил» был единственным случаем, когда `DETECTION_CLEARED`
  не уходил вообще. Чистую страницу репортит любой контекст (`WALL_LOOKS_CLEAR`), но background
  берёт её только от вкладки, ПОДНЯВШЕЙ стену (`tabId` в записи, не плавающий `campaignTabId`),
  и только после settle ~5с с перепроверкой обоих детекторов.
- **Мьюты сторожа достижимы, а не сняты.** `nativeWalkWatchdog` — единственный бэкстоп нативного
  обхода. Окна меряются от того же нуля, что тишина, и длиннее её: стена 15 мин, ревью 40.
  `logged_out` мьютит только доску, по которой реально идёт обход (`campaignTargetUrl`).
- **Lever-капча = handback** через `handBackJob()`: причина записана, обход двигается.

**Heartbeat: терминальная строка — НЕ признак жизни** (#265). Любая строка `phase: "extension"`
освежает `last_ping_at`, а «⏹ Campaign stopped» пишется ДО опускания флага → пинг
`campaign_running: false` за ней не мог снять флаг (`reconcile_not_running` осознанно щадит свежий
heartbeat, иначе праздная вторая копия убивает работающий прогон — 08-15). Когда свой
`/campaign/stop` не доезжал: зомби на весь `HEARTBEAT_TTL_SECS` = 600 с. Теперь строка с
`metadata.outcome` heartbeat'ом не считается, любая другая с метаданными — считается.

**`/campaign/queue?mode=auto|tap`** (#265): сервер резал дневной бюджет по Lever-строкам, которые
авто-прогон обязан выбросить → «леверная» колода приходила короткой при полном дашборде. Режим
выводится на клиенте из тех же `skipPlatforms`; отсутствующий mode = прежнее поведение байт-в-байт.

**Пинг скриншота = `SCREENSHOT_PING_MS = 2500`** (#265; было 300 мс на каждой вкладке под
манифестом, включая личный сёрфинг — ловушка «SW жив на старом коде» + батарея).

## Сломано / не доделано

- **`walkParkedUntil` не сделан** — живость паузы выводится из возраста записи; человек, решающий
  капчу на 15-й минуте, получит один релоад. Достижимо только вне `manifest.matches`.
- `detectSleepGap` обновляет `walkAliveAt`, но не `captchaWaiting.at`: проспанная стена считается
  протухшей на первом тике после пробуждения.
- **Версия ext НЕ поднята и НЕ синкана** — за релизной сессией; #264/#265 у юзеров нет.

## Следующий шаг

Поднять версию, синкнуть (`../scripts/sync-ext.sh` + OFF/ON) и проверить живьём недоказанное:
решить капчу на Indeed и убедиться, что баннер гаснет САМ («Human check cleared — campaign
resumed» в ленте), а прогон идёт дальше.
