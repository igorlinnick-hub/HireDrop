# Affiliate (аффилиатка)

Обновлено: 2026-09-22 · ветки: HireDrop#198 + clicks/console (эта), hiredrop-website#161 + дизайн

## Состояние

Цепочка построена и **проверена вживую на боевой БД** (два временных пользователя,
удалены после прогона): `?ref=` → `profiles.attribution` → `referrals` → `invoice.paid` →
`commissions` → `charge.refunded` → reversed. Плюс `affiliate_stats()` и RLS прочитаны
**под JWT самого аффилиата**: видит только свои строки, `referrals` невидим совсем,
не-аффилиат получает пусто.

**09-22 добавлено:** счётчик открытий ссылки (`affiliate_clicks`, миграция применена в прод),
консоль аффилиатов в админ-борде (одобрить заявку / выдать ссылку кнопкой, без терминала),
дизайн-проход по `/affiliate` и `/affiliate/apply` (панель-картинка с кружками людей), и
исключение из гейта онбординга для `/dashboard/affiliate` — амбассадор, который сам работу не
ищет, больше не обязан проходить квиз с резюме.

Ссылки выдаются **руками** — решение Игоря 09-15. Само-регистрации нет и не планируется
на 5–10 партнёрах: воронка регистрации дороже разговора, а открытая регистрация — это
как раз то, через что аффилиатки набиваются мёртвыми аккаунтами.

Живой оплаты через реферальную ссылку **ещё не было** — начисление доказано на честном
вызове `accrue_from_invoice` с боевым Supabase, но не на реальном платеже Stripe. Ровно
тот класс разрыва, который на кассе дал #145/#147 (моки зелёные, прод падает).

## Решения, которые не надо переоткрывать

- **Начисление от ДЕНЕГ, не от регистрации.** `invoice.paid`, не `checkout.session.completed`
  и не signup. Реферал, который не платит, стоит $0.
- **Ставка живёт в `affiliates.commission_pct`, не в коде.** Поменяем программу — прошлым
  партнёрам обещанное не перепишется. В `commissions.commission_pct` она ещё и заморожена
  на момент начисления.
- **Идемпотентность — это `commissions.stripe_invoice_id UNIQUE`**, а не наша логика.
  Stripe доставляет at-least-once.
- **Аффилиат не читает `referrals`.** Политики на таблице нет вообще: суммы — да, «кто
  именно зарегистрировался и когда заплатил» — нет.
- ~~**Кликов в дашборде нет.**~~ **Снято 09-22**: счётчик появился, плитка «Link opens» тоже.
  Правило осталось верным и сработало как задумано — плитку добавили ровно тогда, когда
  за ней встали данные. Дедуп: одна строка на посетителя, код и сутки (уникальный индекс),
  чтобы перезагрузка страницы не раздувала партнёру трафик.
- **Печатные коды считаются наравне с партнёрскими.** `?ref=card` / `stka` / `stkb` — не
  аффилиаты и никогда ими не станут, но именно они отвечают на вопрос «какой носитель
  сканируют». Поэтому у `affiliate_clicks.code` нет внешнего ключа.
- **Онбординг обходится ровно для одного роута.** `/dashboard/affiliate` открыт тому, у кого
  уже есть строка в `affiliates`; всё остальное по-прежнему требует квиза. Отдельный логин
  для аффилиатов ОТВЕРГНУТ: одна авторизация — одна поверхность для дыр, а партнёров 5–10.
- **Комиссия, уже выплаченная (`paid_out`), при рефанде не отзывается автоматически** —
  деньги ушли из PayPal. Пишется в stderr, разбирается руками.
- **Выплата не раньше 30 дней** после начисления (окно рефанда Stripe) и не ниже $25 —
  `affiliate_admin.py payout` не советует, а отказывает.

## Как работать

```bash
# выдать код (аккаунт HireDrop у человека уже должен быть)
.venv/bin/python scripts/affiliate_admin.py issue lauren@uni.edu --code lauren
.venv/bin/python scripts/affiliate_admin.py list           # реестр + деньги
.venv/bin/python scripts/affiliate_admin.py ledger lauren  # его комиссии
# сначала отправить деньги, ПОТОМ записать:
.venv/bin/python scripts/affiliate_admin.py payout lauren --ref <paypal-txn> --yes
```

`issue` сам подтягивает тех, кто уже успел зарегистрироваться по этому `?ref=` — триггер
срабатывает только на новых записях attribution.
