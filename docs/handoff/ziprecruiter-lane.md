## 0. Итог одной строкой

Причина «0 подач на ZR» была не одна. В одном пути нашлось **15 багов**; все подтверждены
живьём, все починены и смержены (#106, #107, #108), ext **1.4.4 → 1.5.7**. Кампания
больше не умирает молча посреди заявки, а каждая заявка кончается либо подачей, либо
возвратом с причиной.

## 1. Два главных открытия

**(а) Движок жал не ту кнопку.** `findFormButton()` искал по всему документу, а строка
поиска ZipRecruiter — это `form button[type="submit"]`. Движок заполнял модалку и жал
**«Search»**, тот перезагружал выдачу поверх формы. Снаружи — «форма открылась, через 30 с
следующая вакансия» (08-12, 08-14). Не находили, потому что решения `phase3` писались
только в попап: в долговечном логе не было НИ ОДНОЙ строки о выбранной кнопке.

**(б) ZR подаёт заявки без кнопки Submit.** Последний шаг тоже называется «Continue».
08-15 ушли **две реальные заявки** (Soccer 5, Mika Coral Gables — обе «Applied Today» в
ZR → My Jobs → Applied), и движок их не записал: ни счётчика, ни ключа дедупликации →
подал бы повторно. Отсюда «0 подач» в дашборде при живых подачах в аккаунте.

## 2. Все 15 багов

| # | Баг (подтверждён живьём) | Фикс |
|---|---|---|
| 1 | Поиск кнопки по всему документу → жали «Search» в шапке ZR | Скоуп на видимую модалку + deny-list `search/close/cancel/back/save & exit/skip` |
| 2 | У ZR **несколько** видимых `[role=dialog]`; форма — не первая | Перебираем все, сначала с полями |
| 3 | Кнопка шага «Continue Application» не матчилась → заявка брошена | Матч по префиксу |
| 4 | Филлер заполнял только `required`; у ZR **нет** `required` → шаг уходил пустым, Continue отказывал 20 раз | Заполняем любое видимое пустое поле в модалке |
| 5 | Филлеры искали поля по всему документу (доставали страницу за модалкой) | `formScope()` |
| 6 | `waitForFormReady` видел страницу ЗА модалкой → «готово» в момент перерисовки шага | Модаль-aware ожидание + ждём смену шага после клика |
| 7 | Последний «Continue» = submit, не распознавался → **реальные подачи не записывались** | `detectSilentSubmission()` |
| 8 | Уже поданные вакансии заново шли через fit-судью и письмо (деньги) | Проверка «Applied» первой |
| 9 | Форма могла молча топтаться 20 кругов | Stall-guard: 2 круга без прогресса → `handBackJob` с причиной |
| 10 | Харвест ловил только «Quick apply», а ZR мешает его с **«1-click apply»** на одной странице → половина нативной выдачи невидима | Регексп принимает оба |
| 11 | Fit-судья и письмо звались ДО проверки нативной кнопки | Гейт нативной подачи первым |
| 12 | Chrome при рестарте воскресил 9 старых окон автоматизации — все начали работать разом | Автоматизирует только вкладка кампании (fail-open) |
| 13 | Домашняя страница ZR распознавалась как форма → phase3 работал по ней | Не-джобовые пути ZR не могут быть формой + сброс `currentJobInfo` на старте |
| 14 | **Живую кампанию убивал heartbeat**: он держался только на MV3-алярме, который Chrome тормозит на простое → TTL 150 с истекал → флаг снимали как зомби прямо посреди формы | Строка активности от контент-скрипта = heartbeat кампании |
| 15 | **Второе (простаивающее) расширение** пингует «не работаю» под тем же аккаунтом и гасит чужую кампанию | Заявка «не работаю» больше не побеждает свежий heartbeat; в пинге появился `instance_id` |

## 3. Как это ловилось (диагностика, которой раньше не было)

- `STEP N [платформа] filled=[…] btn="…" (dialog|page) → SUBMIT|continue dialogs=…` — на каждый шаг формы.
- `Content script alive on … (ext 1.5.7)` — версия в каждой строке.
- Каждая остановка кампании называет себя: сервером, закрытой вкладкой, закрытым окном, вручную.
- `🔎 campaignRunning true → false (storage write)` — датчик на сам факт записи флага.
  Именно он доказал, что флаг гасил **не** работающий экземпляр расширения.
- Возврат человеку называет поля-блокеры (`unfilled: ['address','state','postal']`).

## 4. Где сейчас стоим

✅ Кампания живёт: последние прогоны идут 5+ минут, проходят несколько вакансий,
не умирают. Инвариант держится — подача или честный возврат с причиной и ссылкой.

⏳ **Не доказано:** сквозная ЗАПИСЬ подачи на текущем билде (`✅ Applied … verified` +
`today_count > 0`). Механика подачи доказана (2 заявки в ZR Applied), но каждая попытка
после фиксов упиралась в следующий блокер (см. ниже).

🔴 **Текущий блокер — не баг движка, а нехватка данных профиля.** На контактном шаге ZR
отказывается принимать «Continue», когда пустые `address / state / postal` (хотя сам
помечает их Optional). У нас есть только город. Заполнять их выдумкой нельзя — это
нарушает инвариант честной подачи. Нужен профильный шаг: улица + штат + индекс.

## 6. Ground truth и инструменты

Правда о подачах — только аккаунт платформы:
`ziprecruiter.com/candidate/my-jobs` (**Applied**) и `/candidate/my-jobs-in-progress`
(**Incomplete**). Пути `/jobseeker/applications` и `/jobseeker/my-jobs` редиректят на поиск.
Свою вкладку ZR закрывать сразу — контент-скрипт инжектится и туда.

Скрипты сессии (scratchpad): `ctail.sh` (лог через curl), `cwatch.sh` (поллер решающих
строк, живость берёт из `/campaign/status`, **не** из `/extension/ping`), `start.js`/`stop.js`,
`pingprobe.sh` (ловит второе расширение), `dom*.js` (дампы модалок).
Токен Supabase — в **cookies** `sb-…-auth-token.0/.1` (base64 после префикса `base64-`).

⚠️ `GET /extension/ping` раньше отдавал `campaign_running` из памяти воркера — живая
кампания читалась как остановленная. Починено (#107), но помни: живость — из
`/campaign/status`.

`background.js` активируется через `HIREDROP_DEV_RELOAD` из вкладки дашборда; в этой
сессии этого хватало и для `content.js` (окно автоматизации создаётся заново).
