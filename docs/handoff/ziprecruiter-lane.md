## 3. Главное техническое открытие: ZR = Downshift

Это то, обо что разбивались все попытки, и оно НЕ угадывается по коду — только живым дампом.

Вопросы «да/нет» у ZR и **обязательное** согласие в «однотаповой» форме — это
**Downshift**-комбобоксы:

```
DIV[role=combobox] name=['sms_opt_in'] vis=true exp=false txt="Open"
  → синтетический клик (pointerdown/mousedown/pointerup/mouseup/click): exp остаётся FALSE
  → ArrowDown:                                                          exp=true
  → меню = <ul> из aria-controls, у него offsetParent === null,
    внутри реальный <li role="option"> «I Agree»
  → без ответа шаг отказывает: «This field is required», aria-invalid=true
```

Отсюда два правила, которые легко потерять при рефакторинге:
1. **Открывать клавишей** (`ArrowDown`), клик — только как дополнение.
2. **Не требовать `offsetParent`** ни от меню, ни от опций: у ZR реальный, кликабельный
   список честно репортит «невидим».

Ещё два тайминга, добытых замером: модалка рендерится **~30 с** в фоновом окне (ждём 40 с,
пустую оболочку считаем external только через 12 с), а выдача кончается на 5-й странице —
две пустые подряд закрывают ключевик (раньше шли до 18-й по 25 с на страницу).

Мост в браузер: `osascript` + вкладка дашборда. Требует **хотя бы одно открытое окно

```bash
# 1. окно дашборда + его id
W=$(osascript -e 'tell application "Google Chrome"
set w to make new window
set URL of active tab of w to "https://hiredrop.io/dashboard"
return id of w
end tell')

# 2. токен Supabase лежит в COOKIES, не в localStorage:
#    sb-…-auth-token.0/.1, склеить, снять префикс base64-, atob → access_token
#    (вытащить через execute javascript в этой вкладке, положить в token.txt)

# 3. дальше всё через curl с этим токеном:
#    GET  /api/v1/activity?limit=200      — лог (единственный durable источник правды)
#    GET  /api/v1/campaign/status         — ЖИВОСТЬ кампании (running)
#    GET  /api/v1/extension/ping          — версия расширения + today_count
#    POST /api/v1/campaign/stop           — погасить
```

⚠️ **Живость кампании берётся из `/campaign/status`, а НЕ из `/extension/ping`.**
Пинг долгое время отдавал `campaign_running` из памяти воркера и врал, что живая кампания
остановлена — час погони за призраком. Починено (#107), но привычка важнее.

Старт кампании — только через мост `window.postMessage({type:'HIREDROP_START_CAMPAIGN', filters})`

Активация правок: `background.js` → `HIREDROP_DEV_RELOAD` из вкладки дашборда; в этой цепочке
этого хватало и для `content.js` (окно автоматизации создаётся заново). Версию проверять
пингом, не «на глаз». После любой правки — `../scripts/sync-ext.sh`.

## 7. Диагностика, которой раньше не было

Именно она превратила «месяцы вслепую» в «баг за 20 минут». Не удалять при чистках:

- `STEP N [платформа] filled=[…] btn="…" (dialog|page) → SUBMIT|continue dialogs=…` — на каждый шаг формы;
- `💥 Form filler crashed: <сообщение> @ <файл:строка>` — раньше исключение не оставляло следа;
- `Content script alive on … (ext 1.7.1)` — версия в каждой строке, устаревшая копия не спрячется;
- каждая остановка кампании называет себя (сервером / закрытой вкладкой / окном / вручную);
- `🔎 campaignRunning true → false (storage write)` — датчик на саму запись флага; именно он
  доказал, что флаг гасил ЧУЖОЙ экземпляр расширения;
- возврат человеку называет поля-блокеры (`unfilled: [...]`), и на платформах без `required`
  список строится из всех видимых пустых полей модалки.

**Правило лейна:** любая слепая зона движка закрывается durable-строкой ДО гипотез.
Решения, написанные только в попап, не существуют — попап умирает вместе с окном.
