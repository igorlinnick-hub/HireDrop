## 0. ГЛАВНОЕ ЗА СЕССИЮ

строки о том, какую кнопку выбрал движок. Теперь есть (`STEP …`).

**Второй факт, который переворачивает статус лейна:** у ZipRecruiter **нет кнопки Submit** —
последний шаг тоже называется «Continue». Сегодня ушли **две реальные заявки**

## 1. Что починено (jobflow `1a0595c` + `14e5d99`, ext 1.4.4 → **1.5.2**, синк на ~/Desktop)

| # | Баг (подтверждён живьём) | Фикс |
|---|---|---|
| 1 | `findFormButton()` по всему документу → кнопка «Search» в шапке ZR | Скоуп на видимую модалку + deny-list `search/close/cancel/back/save & exit/skip` |
| 2 | У ZR **несколько** видимых `[role=dialog]`; форма — не первая | Перебираем все, сначала те, где есть поля |

Диагностика (главный рычаг, если снова «то работает, то нет»):
- `STEP N [платформа] filled=[…] btn="…" (dialog|page) → SUBMIT|continue dialogs=…` — на каждый шаг.
- `Content script alive on … (ext 1.5.0)` — версия в каждой строке, устаревшая копия больше не спрячется.
- На каждом отказе — снимок всех видимых диалогов.

## 2. Как проверять статус ZR (ground truth, не догадки)

ZipRecruiter сам показывает правду в аккаунте Игоря:
- `https://www.ziprecruiter.com/candidate/my-jobs` — вкладка **Applied** (реально поданные).
- `https://www.ziprecruiter.com/candidate/my-jobs-in-progress` — **Incomplete** (начатые и брошенные).

На 08-15 08:25 UTC: Applied = 2 (сегодня), In Progress = 6+ (следы сломанных прогонов 08-12…08-15).
Пути `/jobseeker/applications` и `/jobseeker/my-jobs` редиректят на поиск — не путаться.

⚠️ Смотреть эти страницы **в своём окне Chrome и закрывать его сразу**: контент-скрипт
инжектится и туда, в логе появляется «Content script alive on /candidate/my-jobs» — своя
вкладка вмешивается в прогон.

## 3. Инструменты сессии (в scratchpad, повторить в новой)

Запросы к API идут через авторизованную вкладку дашборда (токен Supabase лежит в **cookies**
`sb-…-auth-token.0/.1`, base64 после префикса `base64-`), osascript `eval(atob('<b64>'))`:
- `act.js` → `/api/v1/activity?limit=300`, `tail.sh <HH:MM:SS>` — чтение лога;
- `ping.js` → `/api/v1/extension/ping` — **живая версия расширения** (проверять ДО прогона);
- `start.js` / `stop.js` — старт-стоп кампании (бэкенд + мост `HIREDROP_START_CAMPAIGN`);
- `dom.js/dom2.js/dom3.js` — дампы диалогов и полей в окне автоматизации;
- `watch.sh` — поллер, шлёт только решающие строки.

`background.js` активируется через `HIREDROP_DEV_RELOAD` из вкладки дашборда — в этой сессии
**этого хватило и для content.js** (окно автоматизации создаётся заново, скрипт инжектится
свежий). Полный OFF/ON на `chrome://extensions` не понадобился ни разу.
