# drop-actions — Drop с кнопками, память ответов о себе, наблюдение за Drop

Обновлено: 2026-10-08 · ветка: **`claude/awesome-heisenberg-r96y2g`** (не смержено, PR не открыт)

## Зачем (Игорь, 10-08)

1. Письмо должно уметь говорить «переезжаю в Сан-Диего» там, где это уместно. Раньше тот, кто
   пишет письмо, не знал даже, где находится вакансия.
2. Вопросы про жизнь человека («готовы переехать в Майами?», «живёте рядом с Остином?»)
   задаются ОДИН раз в расширении и запоминаются. Если спрашивают про другой город, вопрос
   задаётся снова, а рядом показан прежний ответ и предложение «заменить».
3. Drop может достать письмо или заявку, принять новый PDF и пересобрать ATS-резюме. Сам он
   ничего не меняет: только показывает карточку, а меняет её нажатие человеком.
4. Видеть, как Drop используют и где он ошибается.

## Что сделано (бэкенд и расширение 1.8.45 — в ветке)

- **Факты о человеке**: `modules/personal_facts.py` и `app/db/personal_facts.py`, колонка
  `profiles.personal_facts` (`migrations/add_personal_facts.sql`, **НЕ применена**).
  - Один список, три читателя: ответчик на вопросы работодателя, письмо (`in_letters`) и Drop.
  - `reusable()` — запоминаем только обстоятельства человека и вопросы с вариантами ответа.
    Не запоминаем вопросы про ЭТОГО работодателя («this company», «our Austin office»)
    и открытые эссе.
- **Ответчик** (`/tools/answer-question`) работает по шагам:
  1. Тот же вопрос, на который человек уже отвечал → ответ из памяти: без модели и без траты
     квоты.
  2. Вопросы-обстоятельства (переезд, где живёшь, работа в офисе, командировки, смены,
     дата выхода) → только из фактов, по правилам unattended. В кэш не идут.
  3. Если ответа нет → `{"answer": "", "ask_person": {topic, question, related}}`.
  - Модель видит `Job Location`. Отпечаток фактов (fingerprint) входит в ключ кэша скринера.
- **Эндпоинты** (`app/routers/personal.py`):
  - `GET /personal-questions` — одна запись на вопрос, сколько вакансий её ждёт, прежние ответы
    на ту же тему.
  - `POST /profile/facts` — сохраняет ответ и раскладывает его по открытым хендбэкам. Вакансия
    уходит в очередь, только когда на ней закрыты все вопросы. Вопрос с вариантами требует
    один из вариантов (иначе 400 `pick_an_option`). До миграции отвечает 503 `facts_not_ready`.
  - `DELETE /profile/facts/{id}`.
  - Ответы из History (`/handbacks/{id}/answers`) теперь тоже запоминаются.
- **Письмо**: строка `Job Location` и блок «упомянуть, где уместно». Indeed-обход сам передаёт
  город. Для ATS город ищется в пуле по `job_url`. `cover-letter-preview` берёт `job_title` и
  `company` отдельными полями (больше нет «your company»).
- **Расширение 1.8.45**:
  - `circumstanceTopic` — порт `topic_of`. Обе стороны гоняют общую таблицу
    `tests/fixtures/circumstance-topics.json`.
  - Радио-группы и выпадающие списки спрашивают сервер ДО запасных вариантов. Раньше
    радио-группа по умолчанию жала «Yes» на «relocate to Miami?». Теперь, если ответа нет,
    поле остаётся пустым.
  - Уведомление «A question only you can answer» показывается один раз на вопрос; клик
    открывает попап.
  - В попапе карточка «Only you can answer this»: прежний ответ на ту же тему и галочка
    «This replaces that answer».
- **Drop**:
  - Новые инструменты: `get_recent_applications(query)` с id, `get_application_letter`,
    `get_personal_answers`. `get_account` теперь показывает и состояние резюме.
  - `propose_action` (`modules/buddy_actions.py`) — карточки 6 видов. Путь и метод
    запроса задаёт сервер, а не модель. Каждое значение сверяется с аккаунтом человека.
  - `attachment: "resume_pdf"` → фиксированная заметка: «только что загрузил PDF».
  - `POST /profile/ats/contact` — правит одну строку с городом в ATS-резюме без модели.
- **Наблюдение**:
  - Каждый ход пишется в `activity_log` (phase `buddy`, `trace_id` = turn_id): вопрос, ответ,
    инструменты, карточки, токены и их цена в $, время ответа.
  - `POST /buddy/feedback` — 👍/👎 и что стало с карточкой. Отказы по дневному лимиту пишутся
    с phase `buddy_limit`.
  - Одна формула `app/db/buddy_log.summarize` → секция `buddy` в `/admin/metrics` и скрипт
    `scripts/buddy_review.py`.

## Ежедневный скан Drop (решение Игоря 10-09: не почта, а задача в этом хендоффе)

`scripts/buddy_review.py --sweep` судит вчерашний день (UTC) по правилам `buddy_log.alerts`:
упал, «не знал» ≥2, переспросили ≥2, 👎, кнопка не сработала, ≥3 длинных, упёрлись в лимит,
ответ дороже $0.03. Есть проблема — пишет задачу в секцию ниже (одна запись на день, повтор
заменяет; 14 последних дней). **Только цифры**: репозиторий публичный, вопросы людей сюда не
пишутся — в записи команда, которой их прочитать.

**Шаг в prod-sweep — добавить с Мака** (`~/Code/JobFlow/.claude/skills/prod-sweep/SKILL.md`,
из облака недоступен), рядом с `ai_cost_report.py`:

exit 0 → в сводку одну строку «Drop вчера: N вопросов, $X — чисто»
