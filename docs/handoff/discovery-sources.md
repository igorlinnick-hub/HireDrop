# HANDOFF — источники дискавери: кто реально отдаёт вакансии

Обновлено: **2026-09-03** · ветка `platform/google-jobs-verdict` · **не смержено**
Перепроверка одной командой: `.venv/bin/python scripts/audit_discovery_sources.py`

> Выросло из задачи «добавить Google Jobs» ([`google-jobs.md`](google-jobs.md)): оказалось,
> что Google в списке уже был и молча отдавал ноль. Логичный следующий вопрос — **а кто ещё?**
> Прогнал все восемь зарегистрированных источников живьём. Ещё три оказались мёртвыми,
> и один из них — платформа по умолчанию.

и не мог отличить «сегодня ничего нет» от «этот источник мёртв полгода».

## 2. Главная находка: RemoteOK, платформа по умолчанию

`profiles.platforms` по умолчанию = `{remoteok}`. Скрейпер склеивал ключевик в тег:

```python
# "marketing manager" -> тег "marketing-manager", которого у RemoteOK нет
tags = ",".join(k.lower().replace(" ", "-") for k in keywords[:3])
```

Тега `marketing-manager` у RemoteOK нет — API отдаёт только строку-заголовок, дальше цикл
фильтрует пустоту. Замер:

```
keywords=['marketing']          -> 10 jobs
keywords=['marketing manager']  ->  0 jobs      # ← и никакой ошибки
keywords=['python']             -> 10 jobs
```

То есть **любой пользователь с ключевиком из двух слов** (а это норма: «marketing manager»,
«customer success», «data analyst») получал от дефолтного источника ноль.

**Фикс:** берём весь фид (один запрос, ~100 вакансий) и фильтруем локально, а ключевик-фразу
считаем набором слов — все слова должны встретиться, в любом порядке. Тег-словарь RemoteOK
больше ни на что не влияет. После фикса: `marketing manager` → 10 вакансий.

## 3. Что сделано с остальными

- **glassdoor** → `unavailable_reason`. HTTP 400 + «location not parsed» на `remote`,
  `United States` и `New York, NY` — это не формат локации, это мёртвый путь. С витрины сайта
  убран ещё 08-01, в реестре бэкенда оставался.
- **wellfound** → `unavailable_reason`. `wellfound.com/role/r/{query}` = 404, а селекторы в
  коде — от страницы, которой давно нет (там SPA).
- **ziprecruiter** → в `SERVER_SCRAPE_SKIP`, как Indeed. Это **не** поломка подачи: ZR
  остаётся VERIFIED, его вакансии находит нативный обход в расширении. Мёртв ровно серверный
  путь (Cloudflare 403), и теперь он честно называется браузерным.
- **indeed** — без изменений, он уже был в скипе.

Инвариант закреплён тестом: *любая зарегистрированная платформа либо скрейпится, либо
объясняет себя*. Молчаливый ноль больше не проходит ревью.

---

## 4. Как проверять дальше

```bash
.venv/bin/python scripts/audit_discovery_sources.py               # дефолтный ключевик
.venv/bin/python scripts/audit_discovery_sources.py "data analyst"
```

`exit 0` = каждый источник либо отдал вакансии, либо несёт причину. `exit 1` = кто-то снова
отдаёт молчаливый ноль. Гонять после любой правки скрейпера и всегда, когда «Find Jobs»
выглядит подозрительно тощим. Скрипт ходит в живые сайты — поэтому вне CI.

---

## 5. Что это значит для роадмапа

Три из пяти «мёртвых» — борды, которые мы и так не считаем стратегическими (Glassdoor,
Wellfound, Google). Но два вывода дороже самих фиксов:

1. **Дефолтный источник был сломан для типичного ключевика.** Это не про Google и не про
   агрегаторы — это про то, что первое впечатление нового пользователя («нажал Find Jobs —
   пусто») могло быть сломано месяцами, и ни один дашборд этого не показывал.
2. **Тихий `[]` — наш системный класс багов.** Третий случай подряд: неверный пакет
   `jobspy` (#113), Google Jobs, и теперь эти четыре. Лечится не бдительностью, а тем, что
   у источника есть ровно два допустимых состояния — отдаёт вакансии или объясняет почему нет.
