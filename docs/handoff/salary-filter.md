## Состояние

Вилка юзера применяется там, где тратится слот: `on_search_filter` (`app/routers/jobs.py`) —
общий гейт **деки И авто-ATS-очереди**. Правило: «плата не указана → ПРОПУСКАЕМ», если юзер сам
не включил `salary_listed_only`. Правило выбрал ЗАМЕР (`scripts/measure_salary_fill.py`, живой
пул 4261 строка / 124 заявки, 09-26):

| | число |
|---|---|
| задали вилку | **2 аккаунта из 40** ($65k, $100k); listed-only — 0 |
| читаемая плата | **13.3%** · Indeed 44% · GH 8.9% · Lever 1.6% · **Ashby 0% · Workday 0%** |
| «unknown пропускать», флор $100k | дека **93.1%**, заявки 91.1% |
| «unknown режектить», флор $100k | дека **6.7%**, заявки **0.8%** (1 из 124) |

Жёсткий гейт схлопнул бы колоду — ровно ошибка, разобранная с городом. Продуктового решения лейн
больше НЕ ждёт. Ashby 0% — не баг парсера: из 400 строк «$» есть в 154, и ни один не про плату
(раунды, ARR, экономия клиентов).

**Парсер выбирает точность, а не полноту.** Под «unknown пропускаем» навредить может только ЛОЖНОЕ
чтение: отбросить вакансию способно лишь распознанное число. Поэтому сумма считается платой при
платёжном маркере рядом или периоде сразу после неё, и у каждого периода своя полоса
правдоподобия (час 7–400, месяц 1.2k–60k, год 15k–1.5M). Живые ловушки, которые раньше читались
как зарплата: `$50K to $30M+` (бюджеты проектов), `$650 Health Benefit Stipend` после слов
«hourly compensation» (→ $1.35M).

**Замер нашёл баг, которого не видел никто из читавших код:** Indeed склеивает свой чип без
пробела — `$210,000 - $250,000 a yearFull-time403(b)` — и `\b` после «year» не срабатывал; теряли
настоящую плату в **319 из 900** строк Indeed (fill по Indeed 6% → 44%). Вторая грабля там же:
под `re.IGNORECASE` голый `[a-z]` в lookahead ловит и «F», из-за чего первая версия фикса
отвергла вообще всё → нужен `(?-i:…)`.

Тесты: фикстуры `REAL_PAY` / `REAL_NOT_PAY` СКОПИРОВАНЫ из пула (`tests/test_salary_filter.py`);
`tests/test_salary_gate.py` гоняет гейт на обоих путях — 4 из 6 падают, если убрать одну строку
из `on_search_filter` (проверено удалением).

## Сломано / не доделано

- 🚧 **Нативный путь Indeed/ZR зарплату не фильтрует** — и это главная дыра по объёму: подача идёт
  прямо из выдачи (`background.js` ~898 `pickNextStage` → `content.js`), пул не проходит, серверный
  пост-фильтр физически не достаёт. Правильный ход — URL-параметр зарплаты Indeed (у них
  структурированная плата). Лейн расширения: `campaignFilters` (`app/routers/campaign.py:256` +
  `CampaignStartRequest`, `app/schemas.py:82`) зарплатных полей не несёт; добавлять вместе с
  чтением в content.js, и не одновременно с чужими правками в `chrome-extension/`.
- `jobs.py` `describe_job` хранит текст с реальной платой, но никто не перепроверяет — medium,
  скептиками не проверялся; гейт показа перекрывает частично.
- Замер гонять ПОВТОРНО после любой правки парсера: он единственный ловит регрессию «чип Indeed
  перестал читаться».
