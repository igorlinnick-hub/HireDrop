## Состояние

Зарплатная вилка юзера теперь применяется там, где тратится слот: `on_search_filter`
(`app/routers/jobs.py`) — общий гейт **деки И авто-ATS-очереди**. Правило — «плата не
указана → ПРОПУСКАЕМ», если юзер сам не включил `salary_listed_only`.

Правило выбрано замером, а не вкусом. `scripts/measure_salary_fill.py` (09-26, живой пул
4261 строка, 124 заявки):

| | число |
|---|---|
| аккаунтов задали вилку | **2 из 40** (флоры $65k и $100k), listed-only — 0 |
| строк с читаемой платой | **13.3%** · Indeed 44% · Greenhouse 8.9% · Lever 1.6% · **Ashby 0% · Workday 0%** |
| «unknown пропускать» при флоре $100k | дека **93.1%**, реальные заявки 91.1% |
| «unknown режектить» при флоре $100k | дека **6.7%**, заявки **0.8%** (1 из 124) |

То есть жёсткий гейт схлопнул бы колоду — ровно ошибка, разобранная с городом. Вариант (a)
принят и в проде; (b) остаётся личным выбором юзера через `salary_listed_only`.

Ashby 0% — не баг парсера, проверено глазами: из 400 строк Ashby в 154 есть «$», и ни один
не про плату (раунды, ARR, экономия клиентов). Пул платы просто не несёт.

## Последний заход

- **Парсер переписан на точность** (`modules/salary_filter.py`). Под «unknown пропускаем»
  ЕДИНСТВЕННЫЙ способ навредить — прочитать плату там, где её нет: только распознанное
  число может отбросить вакансию. Теперь сумма считается платой, если рядом платёжный
  маркер («salary», «base pay», «compensation», «hourly») или период сразу после суммы, плюс
  своя полоса правдоподобия на каждый период (час 7–400, месяц 1.2k–60k, год 15k–1.5M).
  Ловушки из живого пула, которые раньше читались как зарплата: `$50K to $30M+` (бюджеты
  проектов → $50k), `$650 Health Benefit Stipend` после слов «hourly compensation» (→$1.35M).
- **Найдено замером, а не чтением кода**: Indeed отдаёт свой зарплатный чип БЕЗ пробела —
  `$210,000 - $250,000 a yearFull-time403(b)` — и `\b` после «year» не срабатывал. Мы теряли
  настоящую плату в **319 из 900** строк Indeed (fill по Indeed 6% → 44%). Вторая грабля там
  же: под `re.IGNORECASE` голый `[a-z]` в lookahead ловит и «F», из-за чего первая версия
  фикса отвергла вообще всё. Обе закрыты, обе в фикстурах.
- Фикстуры тестов **скопированы из живого пула**, не сочинены (`tests/test_salary_filter.py`,
  таблицы `REAL_PAY` / `REAL_NOT_PAY`).
- `tests/test_salary_gate.py` — гейт доказан на путях: 4 из 6 тестов падают, если убрать
  одну строку из `on_search_filter`. Сьюта 596/596.

## Сломано / не доделано

- 🚧 **Нативный путь Indeed/ZR зарплату по-прежнему не фильтрует** — и это ГЛАВНАЯ дыра по
  объёму: подача идёт прямо из выдачи (`background.js` ~898 `pickNextStage` → `content.js`),
  пул не проходит, сервер этих карточек не видит. Наш пост-фильтр физически не достаёт.
  Правильный ход — вариант (c): отдать зарплату URL-параметру поиска Indeed (у Indeed
  структурированная плата на своей стороне, наш парсер ей не конкурент). Это лейн расширения:
  `campaignFilters` (`app/routers/campaign.py:256` + `CampaignStartRequest`,
  `app/schemas.py:82`) НЕ несёт зарплатных полей, добавлять их вместе с чтением на стороне
  content.js. Одной сессией не делать вместе с чужими правками в `chrome-extension/`.
- `jobs.py:757` (`describe_job` хранит текст с реальной платой, никто не перепроверяет) —
  medium, скептиками не проверялся, гейт показа его частично перекрывает.
- Замер стоит гонять ПОВТОРНО после любой правки парсера: он единственный ловит регрессию
  вида «чип Indeed перестал читаться» (см. выше — так и нашли).
