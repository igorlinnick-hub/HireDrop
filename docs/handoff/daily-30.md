# daily-30 — живой список заранее оценённых вакансий

Обновлено: 2026-09-30 · ветка: main

## Состояние
- **Шаг 1 в проде (#286):** `modules/fit_queue.py` судит ATS-строки пула ЗАРАНЕЕ, вердикт в
  `jobs.fit_*`; `fit_version` = `ai_fit_judge.verdict_version` (резюме + prefs + планка + промпт),
  несовпадение = переоценка. Сбой судьи и пустое резюме НЕ пишутся: строка «не оценена».
- **Шаг 2 (#289 бэкенд, web #226):** один порядок для экрана, auto и tap — **только свежесть**,
  балл = фильтр (ниже планки — вон), не ранг. `GET /jobs/deck` = список на сегодня: ATS по правилу
  auto (`_ats_candidates`) + Indeed → тот же `build_queue()` (планка, кап 2/компанию/60д) → ≤30
  (`DAILY_LIST_SIZE`). `fits_today` = только прошедшие судью; Indeed не судится заранее и едет
  «Fit checked when applying». Чтение колоды судью не зовёт; неоценённые ATS досуживает фон
  (`_prejudge_in_background`, раз в 60 с/юзер). Устаревший вердикт с карточки срезается.
- Сайт: дашборд — `TodayList` вместо архивной `JobsTable` (удалена); плитка «Jobs Found» (пул)
  → «Fit you today»; Tap больше не мешает платформы и не пересортирует — порядок сервера.
- Решения Игоря — память `project_daily_30_shortlist` (подпись «N fit you today» без «из 30»,
  порядок = свежесть, Indeed в том же списке без счёта).

## Сломано / не доделано
- **Заметка судьи звучит как отказ** даже у прошедших: промпт просит `reason` «why apply or
  skip», на широкой планке это перечень минусов. На карточке подписано «Judge's note», не
  «почему подходит». Править промпт = бамп `PROMPT_VERSION` = переоценка всего пула (~$0.0067/строка).
- При свежести на планке 35 сверху много слабых (38–42) — это выбор планки, не порядка.
- History (`HistoryInsights`) всё ещё показывает «Jobs found» / «New jobs today» (размер пула) —
  другой экран, ждёт слова Игоря.
- Эффект на минуты/заявку не замерен — `GET /tools/run-report` на ближайшем прогоне.
- Цена $0.0067/вакансия: 63% уходит в Sonnet (полоса ±15), строки без описания — зря.
- Судья у Антонии считает её coordinator (режет «Manager») и выдумывает зарплатный порог.
- `company` у GH = токен борда («doordashusa») — с Indeed «DoorDash» кап не склеит.
- Indeed/ZR заранее не судятся (шаг 3): 47–99% строк без описания на сервере.
