# drop-finish — хендбэк доводится роботом, человек делает один шаг

Обновлено: 2026-10-09 · спека утверждена Игорем, код не начат

## Состояние

Спека утверждена Игорем 10-09, код не начат. Три пункта, все требуют `content.js` (ext-лейн, один писатель):

1. **Логистика → «Yes» по умолчанию.** Офис N дней, релокация, смены/график, выезды: всегда «Yes»,
   человека не спрашиваем (память `logistics-answer-yes`). Не трогать: выдуманный опыт
   (`adapt-not-invent`), аттестации «я человек» (`answerer-only-the-person`), визу (флаги профиля).
   Кейс: Suno/Ashby чекбоксы «Yes.» / «No. I want to work remote.», сейчас `fillCheckboxes` их пропускает.
2. **Копия вопросов и ответов в History на КАЖДОЙ заявке.** Все вопросы формы + что робот ответил
   (не только логистика). Нужно: ext шлёт пары Q→A с заявкой, бэкенд хранит, сайт показывает в ряду
   History. Это видимость для человека перед интервью.
3. **«Let Drop finish it»** вместо «Finish form ↗» (web `HistoryView.tsx`, #316). Сейчас ссылка
   открывает ПУСТУЮ форму: ничего не сохраняется (Ashby/GH гостевые формы пустые при каждом
   визите, ZR `lk=` может открыть пустую панель). Игорь: «в чём смысл тогда».

## UX пункта 3 (дословно утверждено)

- Кнопка «Let Drop finish it», **без подписи под ней**.
- Открывается отдельное видимое окно с формой.
- Сверху плашка Drop: «Заполняю за тебя, не трогай, ~1 мин» + прогресс «шаг 2 из 4».
  Именно «~1 мин»: простая форма ~20–40 с, многошаговая 1–2 мин (оценка, не замер).
- В History ряд показывает «Filling…».
- На стене плашка меняется: «Твой ход 👇». Капча подсвечена: «пройди проверку и нажми Submit»;
  email-код: «код пришёл на почту от <ATS>, вставь сюда».
- После Submit окно закрывается само, ряд → «Applied ✓» + копия Q&A.
- Не вышло → плашка «Не получилось, вот форма, допиши сам», ряд остаётся.
