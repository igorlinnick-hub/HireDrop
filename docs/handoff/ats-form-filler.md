# ats-form-filler

Обновлено: 2026-08-14 · ветка: main (последние правки — PR #92, #93, #94, #95)

## Состояние

Филлер сложных ATS-форм в `content.js`. Инвариант держится вживую: каждый одобренный джоб
заканчивается ровно одним из двух — **подан полно-и-честно** ИЛИ **возвращён человеку с причиной
и ссылкой** («✋ Needs your hands»). Тихой полусмерти нет: заблокированный валидацией сабмит
больше не считается за Applied, счётчик откатывается.

Инфраструктура ответов: `pickOptionDeterministic` (демография → decline, eligibility → из профиля,
salary → ближайшее) + `fillTextQuestions` (keyword-map) + AI-фолбэк `ANSWER_QUESTION` +
`chooseOption` с безопасными дефолтами. Детерминированное покрытие ~49%, AI-звонков на заявку
4.10 → 2.98. Бюджет 8 AI-звонков на форму — макс-формы не грайндят по 10 минут, остаток полей
уходит в быстрый hand-back.

Частотный леджер незаполненных полей — `chrome.storage.unfilledLedger`. Он и решает, какой
хендлер строить следующим: не по интуиции, а по реальной частоте.

## Последний заход

- Split sponsorship ≠ work-authorization (#92) — это разные вопросы с противоположными честными
  ответами, слепой «Yes» на sponsorship = неверный knockout под именем юзера. Только из профиля.
- `get_profile` начал возвращать `linkedin_url` (#93) — это был корень топ-1 hand-back'а.
- React-select драйвер (#94): `[class*="select__control"]` + `.select__option`. GH новый UI рендерит
  `multi_value_single_select` кастомными React-виджетами, `querySelectorAll('select')` их не видел.
- Honesty-фикс (#95): убрано голое `/required/` — оно ловило легенду «* indicates required» и давало
  ложный «0 unfilled». Теперь по leftover + `aria-invalid`/`[role=alert]`.

## Сломано / не доделано

- **React-select драйвер (#94) собран по DOM-конвенции, БЕЗ живого DOM** (браузер был занят).
  До живой проверки на реальной GH react-select форме **не доверять ему на knockout-вопросах**.
- `data/gh_form_schemas.jsonl` — 320 живых GH-схем, оффлайн-полигон. Итерировать маппер надо
  здесь, а не на живых работодателях под именем Игоря.
- Открытые эссе (~12% вопросов) закрыты AI-черновиком. Автономные AI-эссе на массе — сознательно
  НЕ делаем: главный риск репутации, n=1 ≠ валидация.
- Компания-специфичное (~23%) уходит в hand-back. Это нормально, пусть леджер копит частоты.

## Следующий шаг

sponsorship-селектом — до этого knockout-ответам от него не верить.
