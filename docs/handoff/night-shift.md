# night-shift — серверный исполнитель ATS-подач (пока юзер спит)

Обновлено: 2026-10-02 · ветка: main (HireDrop #292; профильные поля — #293, см. `answers-at-signup.md`)

## Состояние

`scripts/night_shift/executor.py` (Playwright headless) идёт по **той же очереди, что расширение**
(`_ats_candidates` + `_prejudged_queue`: сохранённые вердикты, бар, свежие первыми, кап 2 на
компанию за 60 дней), Greenhouse и Ashby. `--max N` — заявок за запуск (дефолт 1); стоп: N
отправлено, кап, либо 3 отказа сабмита всего. Dry-run по умолчанию, `--live` явный.

Ответы — `common.answer()`: сначала то, что ЗНАЕМ (зарплата = `profile.salary_expectation`,
«откуда узнали» = карьерная страница, «живёте ли в X» = сравнение с городом/штатом, длинные
списки печатаются из профиля), потом общий ответчик в режиме `unattended` — вопрос про
обстоятельства человека без ответа в резюме/профиле возвращается пустым. Пустое обязательное
поле и любой неподтверждённый сабмит = **хендбэк** (строка `handbacks` + activity `outcome=`);
открытый хендбэк ночью не переоткрывается, нокаут уходит из пула.

Сухой проход по живой очереди Игоря 10-01: 14 форм → **4 готовы** (DoorDash ×2, Tia, Hightouch),
8 хендбэков, 2 нокаута.

## Первая живая подача с Railway (10-01, 22:10 UTC)

Сервис `night-shift` в проекте `virtuous-surprise` (отдельно от `web`; Dockerfile
`scripts/night_shift/Dockerfile` через `RAILWAY_DOCKERFILE_PATH`, вход `railway_run.py`, переменные
`NS_USER/NS_PLATFORM/NS_MAX/NS_LIVE`; ждёт, пока `campaign_states.running` станет false; всегда exit 0,
чтобы рестарт не дал второй проход). Запуск = `railway variables --service night-shift --set NS_LIVE=1`
(переменная передеплоивает → один проход). После прохода `NS_LIVE` возвращён в 0.

- Сухой проход на сервере = как с ноутбука: 14 форм → 4 готовы, 8 хендбэков, 2 нокаута.
- **Живой: 0 отправлено. 3 из 3 сабмитов → `captcha_code`** (Greenhouse: reCAPTCHA score низкий →
  просит код из письма). Это и есть метрика 428 для датацентрового IP: **100% (3/3)**. Ещё 3 хендбэка
  (Muck Rack: местоимения + аттестация «я человек»; Amwell; Later), 1 нокаут. Прогон встал по
  правилу «3 отказа сабмита подряд».
- Вывод: с IP Railway Greenhouse без кода из письма не принимает. Варианты: (а) вводить код из
  почты юзера (нужен доступ к его ящику, код живёт минуты — смена должна ждать письмо на той же
  странице); (б) резидентный прокси; (в) ночью подавать с машины юзера. Решение за Игорем.

## ⛔ ЛЕЙН ЗАКРЫТ 10-02 (Игорь): сервер ночью не заполняет формы вообще

Ни живой подачи, ни разведки (dry-run заполнения). Формы заполняет и подаёт только расширение на
машине юзера. `executor.py` и сервис `night-shift` на Railway (`NS_LIVE=0`) не запускать; код
лежит как история. Ночной СБОР вакансий в пул (`sweep_loop`, `POOL_SWEEP_ENABLED`) — другое,
форм не трогает, работает как раньше. Выжившее из лейна: правила ответчика (#292 — «я человек»,
выдуманная зарплата/страна) живут в общем `ai_question_answer` и защищают расширение.

## Решение 10-02 (Игорь, первое): живой `--live` не делаем

Код из почты = читать личную почту каждого юзера; резидентный прокси = вечная инфраструктура ради
вторичного канала. Это и есть риск, отвергнутый 09-08 (IP не юзера = бан-сигнатура), датацентр
подтвердил его 3/3. Смена остаётся **разведчиком**: `executor.py` по умолчанию dry-run (заполняет,
читает скринеры, раскладывает dry/handback/knockout), `--live` больше не используем, `NS_LIVE=0`
на Railway (сверено 10-02). Ценность — к утру известно, какие формы готовы, а какие ждут ответа.
