# Сессии — кто над чем работает прямо сейчас

Один файл на живую сессию Claude: `<имя>.md` с `lane / goal / now / scope / branch / updated`.
Пишет и читает `scripts/sessions.py`, руками не править. Хендоффы (`docs/handoff/<модуль>.md`) —
память модуля; этот каталог — кто сейчас держит лейн и куда идёт.

## Стандарт (10-08): что гарантирует механизм, а что — сессия

Взят у реестров сервисов (Consul, Kubernetes lease, Eureka): процесс **регистрируется сам при
старте, пульс за него держит среда, при выходе он снимается** — от работника нужно только
объявить намерение. Перенос на сессии Claude: всё, что можно не помнить, делают хуки.

| Что | Кто делает | Хук / команда |
|---|---|---|
| Сессия на доске с первой секунды | механизм | SessionStart → `hook` (статус `open`) |
| Цель из первого запроса («авто: …»), если сессия ещё не заявилась | механизм | UserPromptSubmit → `hook-prompt` |
| Встала на доску, даже если хук старта не сработал | механизм | тот же `hook-prompt` |
| Пульс (`updated`) каждый ход | механизм | Stop → `hook-beat`, раз в минуту максимум |
| Пауза при /clear, снятие незаявленной | механизм | SessionEnd → `hook-end` |
| Лейн, настоящая цель, файлы, шаг, хендофф | **сессия** | `claim` / `beat` / `sign` / `done` |
| Одно напоминание «заяви лейн» на 3-м запросе | механизм | `hook-prompt` |

**Цели (проверяются `python3 scripts/sessions.py stats [--days 7]`, лог наполняют хуки сами):**
1. **Видимость 100%** — каждая работавшая сессия была на доске. Держит механизм; «встала только
   по первому запросу» в отчёте = хук старта не сработал, чинить хук.
2. **Лейн заявлен ≥ 80%** сессий с 3+ запросами (короткий вопрос заявляться не обязан). Без
   лейна доска не видит файлов и не ловит пересечения. Плюс медиана: на каком запросе заявились.
3. **Хендофф при закрытии лейна 100%** — пауза или `done` без хендоффа = следующая сессия начнёт с нуля.
4. **Тихих смертей 0** — заявленный лейн, протухший без паузы (сессию убили, не закрыв).
5. Пересечения файлов при заявке — сигнал, не цель: сколько раз доска поймала столкновение.

Цифры — сравнимые между неделями, потому что считает одна формула (`stats_lines`), а не память.
Лог — `docs/sessions/.events.jsonl`, локальный (в git не идёт): по строке на шаг жизни сессии.

## Как это работает

1. **Имя и место на доске даёт хук, не человек.** SessionStart-хук (`.claude/settings.json`) превращает id сессии
   в `прилагательное-зверь` (`amber-otter`), сразу кладёт её на доску (`open`, «лейн не заявлен»;
   до первого запроса не показывается — пустая вкладка не работа) и печатает доску:
   кто жив, кто протух, где пересекаются файлы. После `/compact` имя то же, и хук печатает
   сессии её ЦЕЛЬ — чтобы сбившаяся вернулась.
2. **Заявка, как только понятна задача:**
   `python3 scripts/sessions.py claim --session <id> --lane ext --goal "ZR-заявки пишутся в History с городом" --now "PR из .wt-zr-truth" --scope chrome-extension/content.js`
   - `goal` — конечный результат одной строкой (что значит «готово»), `now` — текущий шаг.
   - `scope` — файлы/папки, которые правишь. Пересечение с живой сессией = ⚠ в выводе:
     договориться через её хендофф до правки (так однажды два агента сломали content.js).
3. **`/clear` или выход = ПАУЗА, не смерть.** SessionEnd-хук ставит заявке `status: paused`:
   лейн хранит цель, шаг и путь хендоффа. Следующая сессия видит на доске «ПАУЗА [ext] … продолжить»
   и пишет `claim --session <id> --lane ext` без `--goal` — цель, шаг, файлы и хендофф переходят
   к ней. Так экономия токенов через /clear не теряет фокус.
4. **Сменился шаг** — `beat --session <id> --now "…"` (`--handoff <путь>` — где лежит хендофф). Пульс
   (`updated`) хуки обновляют сами каждый ход; заявка, по которой 8 часов не было ни одного хода, — STALE, лейн свободен, следующий `claim` на этот лейн её снимает и говорит об этом.
5. **Хендофф** — первой строкой под заголовком вывод `sign --session <id>`:
   `Сессия: <имя> · лейн <лейн> · цель: … · шаг: … · доска: …`. Кто откроет хендофф, сразу видит,
   чей он и куда идёт. **Лейн закрыт** — `done --session <id>`.
6. `python3 scripts/sessions.py board` — доска в любой момент.
7. **После каждого шага — коммит и пуш в свою ветку** + `beat --branch <ветка>`. Лимит может
   оборвать сессию в любой момент; запушенную ветку продолжит другая сессия (на Маке или в облаке),
   незапушенная работа заперта на одном диске. Когда оживает сессия, чью задачу уже продолжили:
   «подтяни ветку `<ветка>`, свою версию не продолжай».

Заявки коммитятся вместе с хендоффом (`git add docs/sessions/`), иначе облачные сессии их не видят.
Локальные сессии в общем дереве видят их сразу.

## Откуда это (ресерч 10-08)

- Anthropic, «Effective harnesses for long-running agents»: каждая сессия начинается без памяти,
  выживает только файл прогресса + git log; сессия первым делом читает его и пишет перед уходом.
- Параллельные агенты: заявка с арендой (TTL) вместо вечного «в работе», объявленные файлы,
  общий видимый статус — одних локов мало, нужен видимый всем статус, кто что делает.
- Один файл на сессию (как `current_tasks/` в проекте компилятора Anthropic) — нет общего файла,
  значит нет конфликтов при параллельной записи.

## Подключение в корне `~/Code/JobFlow` (локальные сессии Игоря)

Локальные сессии стартуют из корня, не из `jobflow/`, поэтому хук нужен и в корневом
`.claude/settings.json`:

```json
{ "hooks": {
  "SessionStart": [ { "hooks": [ { "type": "command", "timeout": 10,
    "command": "python3 \"$CLAUDE_PROJECT_DIR/jobflow/scripts/sessions.py\" hook" } ] } ],
  "UserPromptSubmit": [ { "hooks": [ { "type": "command", "timeout": 5,
    "command": "python3 \"$CLAUDE_PROJECT_DIR/jobflow/scripts/sessions.py\" hook-prompt 2>/dev/null || true" } ] } ],
  "Stop": [ { "hooks": [ { "type": "command", "timeout": 5,
    "command": "python3 \"$CLAUDE_PROJECT_DIR/jobflow/scripts/sessions.py\" hook-beat 2>/dev/null || true" } ] } ],
  "SessionEnd": [ { "hooks": [ { "type": "command", "timeout": 10,
    "command": "python3 \"$CLAUDE_PROJECT_DIR/jobflow/scripts/sessions.py\" hook-end" } ] } ] } }
```

В `jobflow/.claude/settings.json` (сессии, открытые прямо в `jobflow/`) — те же четыре, путь
`$CLAUDE_PROJECT_DIR/scripts/sessions.py`. Хуки молчат при любой ошибке (exit 0) — сессию
они не ломают никогда. `|| true` на запросе и ходе обязателен: код выхода 2 у UserPromptSubmit
блокирует запрос, у Stop — не даёт сессии остановиться (так ведёт себя argparse на незнакомой
подкоманде, если настройки обогнали код). Порядок включения: сначала код в main, потом настройки.

## Проверка работы друг друга — где да, где нет

Взаимного «скоринга» ботов (каждый ставит оценку каждому) нет и не надо: LLM-оценщик без
проверяемого критерия соглашается и завышает, а токены удваиваются. Проверка есть там, где ошибка
дорогая и есть чем проверить: скептик-агент перед мержем рискованного PR (ext, деньги,
безопасность, удаление данных) + объективные замеры (`run-report`, `run_history.py`, CI).

## Навык handoff (лежит на Маке в корне, из облака недоступен) — что в него дописать

Перед записью хендоффа: `python3 jobflow/scripts/sessions.py sign --session <id>` → эта строка
первой под заголовком хендоффа. После записи: `python3 jobflow/scripts/sessions.py beat --session <id>
--handoff <путь к хендоффу> --now "<следующий шаг из хендоффа>"`. Закрытие сессии (/clear) само
поставит лейн на паузу — следующая сессия продолжит его по `claim --lane <лейн>`.
