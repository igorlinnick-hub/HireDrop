# Сессии — кто над чем работает прямо сейчас

Один файл на живую сессию Claude: `<имя>.md` с `lane / goal / now / scope / branch / updated`.
Пишет и читает `scripts/sessions.py`, руками не править. Хендоффы (`docs/handoff/<модуль>.md`) —
память модуля; этот каталог — кто сейчас держит лейн и куда идёт.

## Как это работает

1. **Имя даёт хук, не человек.** SessionStart-хук (`.claude/settings.json`) превращает id сессии
   в `прилагательное-зверь` (`amber-otter`) и печатает его до первого промпта вместе с доской:
   кто жив, кто протух, где пересекаются файлы. После `/compact` имя то же, и хук печатает
   сессии её ЦЕЛЬ — чтобы сбившаяся вернулась.
2. **Заявка, как только понятна задача:**
   `python3 scripts/sessions.py claim --session <id> --lane ext --goal "ZR-заявки пишутся в History с городом" --now "PR из .wt-zr-truth" --scope chrome-extension/content.js`
   - `goal` — конечный результат одной строкой (что значит «готово»), `now` — текущий шаг.
   - `scope` — файлы/папки, которые правишь. Пересечение с живой сессией = ⚠ в выводе:
     договориться через её хендофф до правки (так однажды два агента сломали content.js).
3. **`/clear` или выход = ПАУЗА, не смерть.** SessionEnd-хук ставит заявке `status: paused`:
   лейн хранит цель, шаг и путь хендоффа. Следующая сессия видит на доске «ПАУЗА [ext] … продолжить»
   и пишет `claim --session <id> --lane ext` без `--goal` — цель, шаг, файлы и хендофф переходят
   к ней. Так экономия токенов через /clear не теряет фокус.
4. **Сменился шаг** — `beat --session <id> --now "…"` (`--handoff <путь>` — где лежит хендофф). Это и есть пульс: заявка без `beat`
   8 часов — STALE, лейн свободен, следующий `claim` на этот лейн её снимает и говорит об этом.
5. **Хендофф** — первой строкой под заголовком вывод `sign --session <id>`:
   `Сессия: <имя> · лейн <лейн> · цель: … · шаг: … · доска: …`. Кто откроет хендофф, сразу видит,
   чей он и куда идёт. **Лейн закрыт** — `done --session <id>`.
6. `python3 scripts/sessions.py board` — доска в любой момент.

Заявки коммитятся вместе с хендоффом (`git add docs/sessions/`), иначе облачные сессии их не видят.
Локальные сессии в общем дереве видят их сразу.

## Откуда это (ресерч 10-08)

- Anthropic, «Effective harnesses for long-running agents»: каждая сессия начинается без памяти,
  выживает только файл прогресса + git log; сессия первым делом читает его и пишет перед уходом.
- Параллельные агенты: заявка с арендой (TTL) вместо вечного «в работе», объявленные файлы,
  общий видимый статус — одних локов мало, нужен видимый всем статус, кто что делает.
- Один файл на сессию (как `current_tasks/` в проекте компилятора Anthropic) — нет общего файла,
  значит нет конфликтов при параллельной записи.

## Подключение в корне `~/Code/JobFlow` (локальные сессии Игоря)

Локальные сессии стартуют из корня, не из `jobflow/`, поэтому хук нужен и в корневом
`.claude/settings.json`:

```json
{ "hooks": {
  "SessionStart": [ { "hooks": [ { "type": "command", "timeout": 10,
    "command": "python3 \"$CLAUDE_PROJECT_DIR/jobflow/scripts/sessions.py\" hook" } ] } ],
  "SessionEnd": [ { "hooks": [ { "type": "command", "timeout": 10,
    "command": "python3 \"$CLAUDE_PROJECT_DIR/jobflow/scripts/sessions.py\" hook-end" } ] } ] } }
```

## Проверка работы друг друга — где да, где нет

Взаимного «скоринга» ботов (каждый ставит оценку каждому) нет и не надо: LLM-оценщик без
проверяемого критерия соглашается и завышает, а токены удваиваются. Проверка есть там, где ошибка
дорогая и есть чем проверить: скептик-агент перед мержем рискованного PR (ext, деньги,
безопасность, удаление данных) + объективные замеры (`run-report`, `run_history.py`, CI).
